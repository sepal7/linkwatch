Connect what you have

No particular router, DNS server or internet provider is required. Start with connection monitoring, then add only the sources you want.

To enable this button: Settings → Apps → Linkwatch → Configuration → set ha_discovery_enabled to true → Save → Restart. Discovery finds existing Home Assistant sensors only; it does not find every network device or configure connections.

Available connectors

Any internet provider: map existing Home Assistant WAN rate sensors in internet_entities. UniFi: optional client inventory and legacy statistics. Pi-hole v6: optional DNS summary and query evidence. Starlink: optional Home Assistant dish sensors. Configure only the hardware you own; omitted connectors stay off.

Connection setup

Leave this dashboard and open Home Assistant → Settings → Apps → Linkwatch → Configuration. Enter only the connections you want, then Save and Restart Linkwatch. These dashboard panels show results; they do not save credentials.

All connections start off. No particular hardware is required. Keep secrets in app Configuration, never in chat or GitHub.

Devices and equipment · UniFi

Set unifi_url to your controller's HTTPS origin (no path) and unifi_api_key to a key from UniFi Network → Integrations. A single site needs no unifi_site_id. After restart, allow a polling cycle for devices to appear.

Optional traffic/signal: set unifi_username and unifi_password for a dedicated local read-only account. The official API alone does not provide those client metrics. Keep TLS verification on; for a self-signed certificate, use unifi_tls_fingerprint with a SHA-256 certificate fingerprint verified through a trusted channel.

Optional application activity: enable unifi_activity_enabled to allow on-demand application reads with that read-only account. Enable Traffic Identification yourself in UniFi if desired; Linkwatch does not change it. The API key optionally supplies application/category names; otherwise IDs are shown. Snapshots stay in memory briefly, never in Linkwatch's database.

DNS activity · Pi-hole v6

Set pihole_url to the local HTTP/HTTPS origin (no /admin or /api path), and pihole_password to an application password from Pi-hole settings. This adds DNS totals; per-device queries also need a current, uniquely matched UniFi client IP.

Prefer HTTPS; HTTP credentials and DNS data travel unencrypted on your LAN. No maintenance, blocking, update or reboot commands are sent.

Internet traffic · Home Assistant sensors

Add your router/provider integration in Home Assistant first. Enable ha_discovery_enabled, save and restart, then use discovery above to find candidate entity IDs. Map your whole-WAN rate sensors in internet_entities, for example download=sensor.example_wan_download and upload=sensor.example_wan_upload. Replace these examples with your own IDs, then save and restart again.

Dish health · Starlink (optional)

Add Home Assistant's official Starlink integration under Settings → Devices & services first. Map its actual sensor IDs in starlink_entities using metric=entity_id, for example latency=sensor.example_dish_ping. Supported metrics: download, upload, latency, loss, connected, update, restart, obstructed and sleeping.

Use only sensors your integration exposes. Bypass setups may need a route configured by you. Discovery does not create that route, and Linkwatch never sends restart/stow commands. Source errors appear above after configuration; missing data is not zero usage.

Setup & delivery limitations

For a speaker on your Pi, set sound_output: local and alerts_enabled: true in app Configuration. Choose the analog/USB/HDMI output in the app's Audio settings, save and restart. A cable alone is not a speaker; use powered speakers. Output availability depends on your host.

For Nest Hub use sound_output: cast and a Google Cast media_player entity; both requests both independently. Home Assistant's local URL must be fetchable by the Hub. Outage Cast playback is best effort: receiver launch may require WAN. Local audio does not depend on WAN or Cast but still requires working host audio. Playback can interrupt media; acceptance does not prove audible sound.

For phone notifications, enter your Companion app's notify.mobile_app_… action in phone_notify_service, then enable alerts. Set sound_output: none for phone-only alerts. Normal push can fail during a home internet outage; Companion Local Push can work on the same functioning LAN when configured on the phone. Dashboard mute covers all outputs.
